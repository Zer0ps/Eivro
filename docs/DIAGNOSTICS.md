# Диагностика Linux

Пункт «Диагностика» в боковом меню проверяет Eivro и состояние системы по кнопке.
В фоне нет периодических проверок сети. Результат хранится только в памяти окна.

Локальная проверка читает интерфейсы, IPv4/IPv6 routes/rules, настройки
systemd-resolved и NetworkManager, resolv.conf, настройки прокси GNOME, активный
профиль и его сетевые выходы, версии компонентов и сохранённую конфигурацию.
Учитываются аппаратные мосты/bond, отсутствие IPv6, сторонние VPN, FakeIP,
занятый локальный порт, оставшиеся TUN/правила и последние сведения подписки.
Доступ к firewall может быть недоступен без прав; это отмечается как непроверенная
область, а не как отсутствие фильтрации.

На основном экране доступны два режима. «На устройстве» выполняет локальную
проверку без внешних запросов. «Доступ к сайту» добавляет DNS/HTTPS-запросы и
позволяет указать домен/IP. Выбор режима сам по себе не запускает проверку:
для запуска нажмите «Проверить». Сравнение с прямым доступом находится в
«Дополнительно» и по умолчанию выключено.
Без адреса используется example.com. HTTPS проверяет сертификат и не следует
перенаправлениям. В TUN отдельно проверяются локальный прокси и системный путь:
успешный ответ ядра сам по себе не подтверждает системный перехват. Исключения
маршрутизации при системной проверке сохраняются. При активном прокси имя
назначения передаётся прокси; отдельная
проверка системного DNS вне него требует согласия на прямое сравнение. Прямое
сравнение запрещено при включённом kill switch. Оно привязывается к физическому
интерфейсу, но сторонняя маршрутизация или firewall всё равно могут влиять на путь.
Диагностика не определяет достоверно ТСПУ, действительность ключа или состояние
удалённого сервера по одному таймауту.

Проверяются сервер выбранного VPN и серверы используемых выходов текущего профиля.
Имена неиспользуемых выходов не запрашиваются. При активном прокси системный DNS
серверов внешних выходов также требует согласия на прямое сравнение.

Основной результат показывает найденные проблемы и незавершённую проверку доступа.
Доказательства и прежние подтверждаемые действия раскрываются в строке результата.
Успешные проверки и ограничения диагностики доступны в «Информация» →
«Технические сведения». Раздел расположен внизу бокового меню и позволяет
просмотреть обезличенный отчёт. Метка BETA обозначает статус диагностики на всех трёх платформах. Справочный результат означает, что проверки недостаточно для
вывода, а не обязательно неисправность. Успешная локальная проверка не подтверждает
доступ в интернет. Проверяется сохранённый активный профиль;
неприменённые правки и собственные DNS/proxy-настройки браузеров не анализируются.

## Исправления

Каждое изменение требует подтверждения. Доступны переподключение Eivro, очистка
кэша DNS и восстановление сохранённой аренды системного прокси Eivro. При пустом
runtime DNS физического подключения можно восстановить адреса из его активной
конфигурации NetworkManager. Поддерживаются аппаратные Ethernet/Wi-Fi и
подтверждённые мосты/bond. Существующие пользовательские DNS не заменяются.

Восстановление DNS допускается только без активного TUN Eivro. Неактивный помощник
завершается через штатную очистку перед отдельной авторизацией. GUI передаёт
помощнику только интерфейс и отпечаток состояния; адреса серверов помощник заново
получает из NetworkManager. Восстановление отклоняется, если системная D-Bus-шина
находится в другом сетевом namespace: числовые индексы интерфейсов между ними
не взаимозаменяемы. Проверяются интерфейс, текущая пустота DNS и неизменность
маршрутов, DNS-областей и источника NetworkManager. Перед записью выполняется повторная
проверка. Меняется только список DNS интерфейса, без `resolvectl revert`.

Отмена до подтверждения записи ничего не меняет. Если запись уже началась, она может
завершиться; приложение сообщает об этом и предлагает повторить диагностику.
После выполненного исправления проводится локальная перепроверка. Перезапуск
NetworkManager, смена DNS на публичные адреса и удаление неизвестных маршрутов или
firewall-правил не выполняются. При неоднозначности предлагается ручная проверка.

## Конфиденциальность и проверки

Не собираются пакеты, история посещений, пароли прокси или полные конфигурации ядер.
Ключи, UUID и ссылки подписок не входят в результат. Экспорт в буфер обмена доступен
после предварительного просмотра и содержит только версию приложения, статические
названия проверок и статусы; динамические детали, адреса и имена исключены.

Есть регрессионные тесты на отмену, устаревшие результаты, изменение DNS во время
авторизации, отказ записи, сохранение сторонних изменений, ограничение вывода и
времени, завершение диагностических процессов вместе с родителем и отсутствие
утечки динамических данных в экспорт. Результаты проверки в ВМ см. в
[VERIFICATION.md](VERIFICATION.md).
