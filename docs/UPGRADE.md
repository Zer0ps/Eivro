# Linux 1.4.0

В боковом меню появился пункт «Диагностика». Проверки запускаются вручную;
внешние DNS/HTTPS-запросы и исправления требуют отдельного выбора.
Восстановление пустого DNS использует активную конфигурацию NetworkManager;
существующие пользовательские DNS не заменяются. Подробнее —
[DIAGNOSTICS.md](DIAGNOSTICS.md).

Исправлены преждевременное завершение помощника при отдельных запусках через
`pkexec` и кратковременный отказ повторного запуска GUI. Формат настроек Linux
остаётся прежним: схема 6. Перед обновлением завершите Eivro штатно. Для отката
на 1.3.5 миграция настроек не нужна. Изменения диагностики относятся только к Linux.

# Linux 1.3.5

Помощник обрабатывает SIGTERM/SIGINT/SIGHUP и потерю канала GUI: сначала
останавливает ядра, затем очищает кэш DNS и освобождает собственную защиту сети.
После аварии ядра убираются оставшиеся policy rules текущего сеанса. Занятый
диапазон приоритетов 9000–9010 вызывает отказ до запуска TUN, чтобы ядро не
удалило ранее установленные правила другого приложения.

Исправлены зависание переключения во время автоподключения, применение обновления
подписки при конфликте маршрутов и пропуск восстановления системного прокси при
повреждённых настройках. Формат настроек Linux остаётся прежним: схема 6.

SIGKILL нельзя перехватить. Если помощник исчез без подтверждения очистки,
приложение сообщает об этом. Одновременное принудительное завершение всех процессов
или стороннее изменение правил во время сеанса не гарантируют автоматического
восстановления; чужие правила не следует удалять массово. Восстановление kill switch
описано в [справочнике](REFERENCE.md). Завершите Eivro перед обновлением пакета.

# Linux 1.3.4

Исправлена совместная работа TUN с сервером другого VPN; настройка описана в
[сетевых выходах](NETWORK-EXITS.md). Отмена авторизации TUN отключает автоматические
повторные запросы до явного нажатия «Подключиться». Приложение остаётся открытым,
предпочтение автоподключения при следующем запуске сохраняется.

Настройки Linux переходят на схему 6. Перед первой записью схемы 5 создаётся
приватная копия `settings-before-1.3.4.json`. Для отката завершите Eivro, сохраните
текущие настройки отдельно и восстановите эту копию с правами 0600. Изменения,
сделанные после миграции, в копию не входят. macOS и Windows пока остаются на схеме 5.
Сборка ядра sing-box и формат временного DNS-состояния не меняются.

# Очистка DNS в Eivro 1.3.3

В Linux штатный полный выход очищает домены из временной таблицы, сохраняя счётчики
FakeIP. Закрытие в трей и переподключение не очищают её. Если приложения продолжают
использовать старые FakeIP после нового запуска Eivro, обновите их DNS-кэш или
перезапустите эти приложения. Проверка TLS и правила маршрутизации не ослабляются.

Формат пользовательских настроек не менялся. Формат указателя временного DNS-состояния
обновлён; при откате на Linux-пакет до 1.3.3 завершите Eivro и перезагрузите ОС,
чтобы очистить tmpfs и кэши процессов. Не удаляйте файлы `/run/eivro-dns` вручную.

# RU-профили в Eivro 1.3.2

Обновление добавляет два готовых профиля маршрутизации, сохраняя текущий выбор и
пользовательские правила. Списки работают офлайн. Изменения настроек записываются
в схеме 5; перед первой записью старого файла сохраняется приватная копия
`settings-before-1.3.2.json` (Windows: зашифрованный `settings-before-1.3.2.dat`).

Для отката сначала завершите Eivro и сохраните отдельную копию актуальных настроек.
После установки старого пакета восстановите файл из указанной резервной копии,
сохранив приватные права доступа. Приложения до 1.3.2 не читают схему 5;
настройки и новые ключи, добавленные после миграции, отсутствуют в старой копии.

# Переход Velum → Eivro

Закройте старое приложение через «Выход» в трее после отключения VPN.
Установите Eivro 1.2.0 или новее обычным пакетным менеджером и откройте из меню приложений.
Пакет `eivro` заменяет пакет `velum`; старого помощника TUN и записи меню не остаётся.
Команды `/usr/bin/velum` и `/usr/libexec/velum/velum` переадресуют запуск в Eivro.
Первое разрешение TUN после обновления относится к новой политике `io.eivro.tun`.

## Данные

При первом запуске под блокировкой единственного экземпляра каталог
`~/.config/velum` переименовывается в `~/.config/eivro` на той же файловой системе.
Если задан абсолютный `XDG_CONFIG_HOME`, используется он. Переносятся настройки,
ключи, импорты, резервные копии и файлы восстановления системного прокси.
Содержимое не отправляется в сеть. В Linux 1.3.4 используется схема 6,
в macOS/Windows — схема 5; старые схемы мигрируют штатно.

Если настройки Eivro уже есть, они имеют приоритет: каталоги не объединяются.
Если каталог Eivro существует без настроек, старый каталог имеет небезопасные права
или настройки повреждены, перенос прекращается с ошибкой без перезаписи данных.

Автозапуск, созданный Velum, обновляется при первом запуске GUI. Исходный файл
`~/.config/autostart/io.velum.Client.desktop` сохраняется как
`io.velum.Client.desktop.before-eivro`. Отключённый автозапуск остаётся отключённым;
существующая запись Eivro не перезаписывается. Произвольные пользовательские
записи не изменяются автоматически.

Служебные имена блокировки процесса, `/run/velum-tun.lock` и nftables-таблицы
`inet velum_guard` сохранены для совместимости. Это предотвращает одновременное
владение туннелем и позволяет очистить защиту после прерванного старого сеанса.
Имя нового интерфейса — `eivro0`.

## Откат

1. Отключите Eivro, завершите его и убедитесь, что помощник освободил TUN.
2. Сохраните отдельную приватную копию `~/.config/eivro`.
3. Удалите пакет Eivro и установите прежний RPM/DEB Velum.
4. Если `~/.config/velum` отсутствует, переименуйте `~/.config/eivro` обратно.
   Если оба каталога существуют, не перезаписывайте их: выберите нужную копию.
5. При включённом автозапуске уберите запись `io.eivro.Client.desktop` и восстановите
   `io.velum.Client.desktop.before-eivro` под прежним именем.

При откате на Velum 1.1.0 схема 4 совместима. Для 1.0.0 нужна сохранённая ранее
копия `settings-before-1.1.json`; новые сетевые выходы в 1.0.0 отсутствуют.
Автоматическая установка, удаление пакетов или переключение рабочего VPN
во время сборки проекта не выполняются.
