# Рабочий VPN вместе с Eivro

В «Маршруты → Сетевые выходы» создайте выход, например **Работа**, укажите
интерфейс рабочего VPN (`tun0`, `wg0` или другое фактическое имя) и DNS:
основной DNS интерфейса либо один IP вручную. Для автоматического чтения DNS
нужен `systemd-resolved` и `resolvectl` с JSON-выводом; если их нет, используйте ручной IP.

В правилах выберите этот выход вместо «Напрямую» и добавьте корпоративные домены
и необходимые IP/CIDR. Например: `company.example`, `*.company.example`, `10.0.0.0/8`.
Нажмите «Применить». Активное подключение переподключится. Для wildcard корневой
домен добавляется отдельно. Первое совпадение имеет приоритет.

Трафик и DNS этого выхода привязаны к одному интерфейсу. Стандартное «Напрямую»
сохраняет прежнее поведение через основной внешний интерфейс. Для рабочего VPN
используйте именованный выход. Основной DNS — первый подходящий адрес интерфейса;
автоматическое переключение на второй DNS пока отсутствует. Ручной DNS не заменяется
на DNS интерфейса. DNS-over-TLS с нестандартными параметрами не преобразуется в обычный DNS.

Если интерфейс выключен, отсутствует или его DNS не найден, совпавшие запросы,
**попавшие в Eivro**, отклоняются. Публичный DNS и сервер Eivro не служат запасным
путём. Это не заменяет системный kill switch: существующие маршруты Linux могут
обходить TUN. Kill switch Eivro несовместим с внешними выходами, поскольку его
firewall также ограничивает транспорт второго VPN; приложение отклоняет такое сочетание.

Изменения интерфейсов отслеживаются через rtnetlink, изменения DNS — через
сигналы systemd-resolved. При изменении используемого выхода Eivro переподключается.
В простое опросов нет. «Обновить интерфейсы» позволяет запросить снимок вручную.
Имя интерфейса не является идентификатором VPN-провайдера: если другой VPN займёт
`tun0`, привязка будет относиться к нему. Предпочитайте постоянное имя рабочего туннеля.

Правила приложений работают в TUN. Для внутренних имён добавляйте также доменные
правила: DNS может выполнять отдельный системный процесс. Собственный DoH браузера
не использует DNS Eivro. В режиме «Прокси» приложение должно поддерживать системный
прокси GNOME; «Локально» требует явной настройки HTTP/SOCKS5.

## Проверки

`./scripts/check.sh` включает проверку конфигов настоящим sing-box и лабораторию
`tests/network_lab.py`: два одноразовых network namespace, интерфейс рабочего VPN,
DNS и HTTPS с проверкой сертификата. Проверяются доступный выход и отказ без новых
DNS-запросов. Реальные настройки, маршруты и DNS хоста лаборатория не меняет.
Для ручного запуска: `cargo build --locked --example network-lab-config`, затем
`python3 tests/network_lab.py`. Нужны Linux, разрешённые user namespaces, iproute2,
OpenSSL и curl.
