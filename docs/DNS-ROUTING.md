# DNS и доменные правила в Linux TUN

В 1.3.1 Linux TUN сохраняет исходное доменное имя через FakeIP. Например,
два имени могут указывать на один CDN-адрес, но иметь разные правила маршрутизации.
Обычная таблица «IP → последнее имя» не позволяет надёжно различить их.

Для перехваченных запросов A/AAAA ядро выдаёт виртуальный адрес из
`198.18.0.0/15` или `2001:2::/111`. При подключении к этому адресу оно
восстанавливает исходное имя, выбирает правило и выполняет настоящее разрешение
имени через DNS выбранного выхода. CNAME не заменяет исходное имя правила.
Распознанный HTTP Host или внешний SNI также не заменяет уже известное имя.

Исключение в Linux 1.3.4 — явно заданные серверы других VPN в сетевых выходах:
они получают реальные IP и обходят TUN на уровне маршрутизации ОС, чтобы их
транспорт не зависел от перезапуска Eivro. Это отдельная настройка, общая для
профилей; обычные правила «Напрямую» продолжают использовать FakeIP.
См. [совместную работу VPN](NETWORK-EXITS.md).

Первое совпавшее правило по-прежнему определяет маршрут. Если профиль содержит
IP/CIDR-правила, перед их проверкой имя разрешается в реальные адреса. DNS выбирает
первое подходящее доменное правило или правило приложения; IP-правило само по себе
не может выбрать DNS до получения IP. Недоступный именованный выход отклоняет
соединение без публичного резервного DNS или другого выхода.

## Переключение и восстановление

Соответствие «виртуальный адрес → имя» сохраняется при переключении сервера и
после аварии ядра или помощника. Реальные DNS-ответы принадлежат отдельному запуску
ядра и не переносятся на новый сервер. Поэтому приложения могут использовать
прежний виртуальный адрес, а новое соединение получит актуальный адрес CDN.
Уже открытые соединения при переключении могут оборваться.

Таблица хранится только в root-owned tmpfs `/run/eivro-dns`.
Она содержит доменные имена: подробности и влияние swap описаны в
[политике конфиденциальности](../PRIVACY.md). Каталог имеет права 0700, файлы — 0600,
размер файла ограничен 32 МиБ. При переполнении адреса не переиспользуются для других
имён. Потеря или несовместимость сохранённого состояния приводит к отказу запуска,
а не к незаметному назначению старых адресов новым доменам. Не удаляйте эту таблицу
во время работы ОС; для её сброса перезагрузите систему.

Начиная с 1.3.3 штатный полный выход удаляет доменные имена, оставляя только
счётчики выделенных адресов до перезагрузки ОС. Помощник создаёт свежую базу только
с метаданными, атомарно переключает указатель поколения и удаляет старый файл.
Сбой до переключения сохраняет прежнюю таблицу; после переключения принимается
только новое поколение. Потеря опубликованного файла не вызывает откат к старому.
Старые страницы базы не копируются в новый файл.

После такого выхода приложения с собственным кэшем FakeIP должны запросить DNS
снова; может понадобиться перезапуск приложения. При новом запуске TUN неизвестные
старые адреса отклоняются. Очистка имён не возвращает адреса в свободный пул: в каждом семействе
доступно около 131 тысячи адресов до перезагрузки ОС. При исчерпании новые запросы
отклоняются, адреса другим доменам не переназначаются. Трей, переключение сервера,
обычная остановка и аварийное восстановление сохраняют таблицу.

Если завершение очистки не подтверждено, окно остаётся открытым с выбором повтора
или явного выхода без очистки. Принудительное завершение не гарантирует удаления
имён. Имена файлов `.cache` и `.cache.next` обозначают два сменяемых поколения;
ни один из них нельзя удалять вручную, определяя активность только по имени.

Помощник очищает кэш активного systemd-resolved после запуска ядра и при полном
отключении. Он не меняет адреса системных DNS или домены другого VPN. Между
остановкой и запуском ядра при переподключении очистка не выполняется.

## Границы

- Изменение включено только в Linux TUN. Windows/macOS и режимы «Прокси»/«Локально»
  сохраняют прежнее поведение.
- Собственный DoH приложения, сохранённые ранее реальные IP и IP-подсказки HTTPS/SVCB
  могут обходить наблюдаемые A/AAAA. Без известного имени работают IP/процессные
  правила и маршрут по умолчанию. Eivro не расшифровывает TLS/ECH.
- Ответ FakeIP не подтверждает существование домена: реальный DNS-запрос выполняется
  при соединении. Приложения со своим DNS-кэшем могут потребовать перезапуска после
  отключения TUN. Постоянный кэш приложения через перезагрузку ОС не поддерживается.
- Зарезервированные диапазоны нельзя одновременно использовать для другой сети.
  Помощник проверяет явные маршруты внутри этих диапазонов перед запуском.

## Ядро и проверка

Linux x86_64 использует `sing-box 1.14.4-eivro.2`, собранный из закреплённого
официального commit с [локальным патчем](../patches/sing-box/README.md).
Это изменённая сборка Eivro, не официальный готовый бинарник SagerNet.

Лабораторные тесты создают отдельные user/network/mount/PID namespaces и приватный
`/run` без сокетов служб хоста. Один network namespace не изолирует D-Bus и
systemd-resolved. Тест помощника дополнительно использует временный chroot.
Запускайте тесты через их обычную точку входа, без ручного вызова режима `lab`.

```sh
python3 scripts/build-core.py --output vendor/sing-box
./scripts/check.sh
```

Проверяются CNAME, разные домены одного IP, TCP/UDP, IPv4/IPv6 FakeIP,
приоритеты доменных/IP/процессных правил, недоступный выход, смена реального
DNS-ответа, повторное подключение и аварии ядра/помощника. Проверка ядра отдельно
покрывает исчерпание диапазонов и несовместимость сохранённого состояния.
Опциональный микрозамер `python3 tests/fakeip_core.py --core vendor/sing-box --bench 1000`
использует только синтетические имена и loopback; он не измеряет всё приложение.

Для проверки установленного кандидата завершите Eivro, установите пакет и снова
запустите приложение. Проверьте свои исключения и обычный проксируемый сайт в TUN,
затем смену сервера и отключение. Откат — завершить приложение и установить
предыдущий пакет; сохранённые настройки совместимы. Если приложение удерживает
виртуальные адреса после отката, перезапустите его или ОС.
