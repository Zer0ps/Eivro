# Windows

Целевая платформа — Windows 10 22H2 и Windows 11, x86_64.
Установщик и подключения проверены в Windows 11. Отдельная проверка Windows 10
на реальной системе ещё нужна; ARM64-сборки пока нет.

Используются общий интерфейс Eivro и официальные ядра. Системный прокси
настраивается для текущего пользователя через WinINET. Приложения, которые
игнорируют системный прокси, должны использовать TUN или явно заданный HTTP/SOCKS5.
Настройки с данными подписок защищаются Windows DPAPI и привязаны к пользователю.

Установщик размещает приложение в `Program Files\Eivro` и регистрирует службу
`EivroTunnel`. Права администратора нужны при установке. Обычное окно работает
без повышения прав. При интерактивной установке доступ к TUN получает пользователь
рабочего стола, в том числе при подтверждении UAC другой административной учётной
записью. При установке без рабочего стола используется учётная запись установщика.
Обновление сохраняет ранее выданный доступ; остальные пользователи его автоматически
не получают.

Переносимый ZIP поддерживает локальный и системный прокси. Для TUN нужна
установленная служба той же версии. Kill switch на Windows пока недоступен.
Бинарные файлы Eivro и установщик пока не подписаны сертификатом издателя;
подпись upstream-драйвера Wintun не является подписью самого приложения.

## Диагностика и маршруты в 1.5.1

В каталоге доступны «Диагностика» и «Информация». Локальная проверка читает
адаптеры и DNS через IP Helper, состояние системного прокси через WinINET,
активный профиль и версии компонентов. «Доступ к сайту» разрешает проверку HTTPS.
В TUN выполняются отдельные запросы через локальный прокси и системный маршрут.
Ручное правило IP/CIDR учитывается и при обращении к прокси по доменному имени.
В TUN Windows использует обычные DNS-ответы и обратное сопоставление sing-box.
Для двух доменов с общим IP выбор маршрута по одному IP может быть неоднозначным.

## Сборка

Нужны x64 Windows, MSVC Build Tools с Windows SDK, Rust из `rust-toolchain.toml`
и Python 3.11+. Из PowerShell в корне проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-windows.ps1
```

ExecutionPolicy задаётся только этому процессу; системная политика не меняется.
Скрипт проверяет закреплённые контрольные суммы ядер, получает проверенный
компилятор Inno Setup и создаёт EXE-установщик, ZIP и SHA-256 в `dist`.
MSVC runtime включён статически; отдельный Visual C++ Redistributable не нужен.

```powershell
cargo test --locked --release -- --test-threads=1
```

Обычные тесты не меняют системный прокси или маршруты. Испытания установленного
TUN запускаются отдельно, только в одноразовой ВМ без существующей установки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke-windows.ps1 -AllowNetworkTests
```

Этот сценарий устанавливает пакет, временно меняет сеть ВМ, проверяет подключение
и восстановление, затем удаляет тестовую установку. Проверяются оба ядра,
TCP/UDP, отдельный DNS и интерфейс, правила приложений, закрытие клиента,
аварийная остановка ядра/службы и восстановление системного прокси.

## Проверка Windows 11

В лабораторной ВМ проверены обычный пользовательский запуск, подписка провайдера
с VLESS/XHTTP/Reality, HTTPS и UDP DNS через TUN. Другой стандартный пользователь
не получил доступ к каналу службы и записи в установленные бинарные файлы.

Открытое окно с подключённым TUN за 30 секунд простоя не накопило измеримого
процессорного времени; Xray использовал 0,016 секунды CPU. Рабочий набор окна
составил около 64 МиБ, private bytes — около 99 МиБ. Это измерение в ВМ с
программным Direct3D, а не обещание одинаковых цифр на любом компьютере.

В Windows 11 с четырьмя виртуальными процессорами и программным адаптером
повторяющиеся проходы мыши через край кнопки занимали около 67% ЦП в исходной
сборке. После исправления тот же сценарий занял около 11%. Клиент обновляет
подсветку сразу при входе и выходе курсора. Пока изображение остаётся прежним,
повторная отправка кадра графическому адаптеру не требуется.

Обработка событий и уведомлений не использует постоянный опрос. Особенности
отрисовки и работы трея описаны в [патче eframe](../vendor/eframe/EIVRO-PATCH.md).
