# Velum

Нативный Linux-клиент на Rust + egui, sing-box 1.14.4 и Xray 26.10.21.
Stable 1.0.0 (`1.0.0`): подписки с обновлением и информацией провайдера,
трей, профили маршрутизации, встроенные эмодзи и восстановление по событиям сети/сна.
Одно разрешение TUN на сеанс приложения. Экспериментальный kill switch включается отдельно.
Телеметрия и логи приложения отсутствуют.

В 1.0.0 исправлены восстановление прокси GNOME после изменения исключений
и зависание системного DNS при подключении/обновлении подписки. Отмена
подключения завершает DNS-процесс; срок DNS сервера — 10 секунд, всей загрузки
подписки с перенаправлениями — 20 секунд. Фонового DNS-процесса в простое нет.

В alpha.7 обновлены официальные ядра и TLS-зависимости: rustls 0.23.46,
rustls-webpki 0.103.16 и webpki-roots 1.0.10. Удалено доверие отозванным
промежуточным сертификатам emSign. Tokio обновлён до 1.53.3.
Сборка и упаковка проверяют закреплённые версии обоих ядер; загрузчики
проверяют SHA-256 официальных архивов. TLS-проверка сертификатов включена.

В alpha.6 HTTPS-проверка подключения ограничена общим сроком 18 секунд.
Зависание ответа прокси или TLS больше не оставляет вечную «Проверку соединения…»: 
проверочный процесс завершается, подключение очищается, появляется ошибка.
Ожидание блокирующее, без дополнительных фоновых опросов.

В alpha.5 исправлена совместимость обновлений Durev с `x-durev-sni-change`.
При ошибке загрузки, проверки или сохранения прежние серверы и выбор остаются
в памяти приложения. Новые данные публикуются после успешного сохранения.

Начиная со сборки alpha.4 ссылки VLESS TCP/Reality, с Vision и без него, используют Xray.
Это применяется и к ранее сохранённым ссылкам: импортировать их заново не нужно.
Во всех режимах Xray привязывается к основному внешнему интерфейсу, как sing-box;
его соединение с сервером не уходит в другой активный TUN. Локальные серверы
на loopback продолжают работать через loopback. Схема настроек не менялась.
Xray закреплён на официальном выпуске 26.10.21; sing-box — на стабильном 1.14.4.
Сборка обновляет старый Xray в `vendor/`, а упаковка отклоняет неподходящее ядро.
Старые параметры XHTTP `sessionPlacement`/`sessionKey` автоматически передаются
ядру как `sessionIDPlacement`/`sessionIDKey`; противоречащие друг другу значения
отклоняются. Это применяется и при загрузке ранее сохранённых профилей.

## Запуск

В папке проекта: `./start.sh`. Готовые пакеты находятся в `dist/`.
Переносимый архив: распаковать и запустить `./velum`. AppImage: дать право
исполнения и запустить. Если FUSE недоступен: `./Velum-1.0.0-x86_64.AppImage --appimage-extract-and-run`.

На Fedora пакет устанавливается вручную:

```sh
sudo dnf install ./dist/velum-1.0.0-1.x86_64.rpm
```

Перед обновлением отключите VPN и выберите «Выход» в меню трея, затем
установите пакет и снова запустите `velum`. Настройки alpha.2–alpha.7 совместимы с 1.0.0.
Версия установленного ядра: `/usr/libexec/velum/xray version` — ожидается 26.10.21.

На Debian-совместимой системе с достаточно новой glibc:

```sh
sudo apt install ./dist/velum_1.0.0_amd64.deb
```

Готовые x86_64-пакеты собраны через Zig с целевым ABI glibc 2.31; максимальная
версия символов итогового исполняемого файла — GLIBC_2.30. Точный нижний
предел записывается в DEB автоматически. Это не заменяет тестирование
на каждом поддерживаемом дистрибутиве.
Графические библиотеки Wayland/X11 и OpenGL/EGL нужны и переносимым сборкам.
Полная проверка выполнена только для окружения, описанного в `docs/VERIFICATION.md`.

## Использование

1. Открыть «Подписки» → «Добавить»: ссылка, Base64, JSON или HTTPS URL; можно перетащить файл/архив в окно.
2. Выбрать подписку, сервер и режим: «Прокси», «Локально» или TUN.
3. Выбрать профиль в «Маршрутах» или открыть «Настроить правила», затем подключиться.

Сервер, режим и исключения можно менять при работающем VPN. Velum сначала
останавливает прежнее соединение, дожидается очистки, затем запускает новое.
Это короткое переподключение: активные TCP-сессии могут оборваться. Без kill switch между
туннелями возможен прямой доступ в интернет.
Отмена во время переключения оставляет приложение отключённым; повторные попытки
восстановления ограничены и не выполняются при выключенном соединении.

В «Подписках» доступны отдельное обновление, удаление и меню интервала:
вручную, по провайдеру или каждые 1–720 часов. По умолчанию используется
`profile-update-interval` провайдера (в часах); если его нет, автоматического
обновления нет. Таймер работает, пока открыт Velum. После пропущенного срока
обновление выполняется при запуске; после ошибки повтор не раньше чем через
5 минут. Одновременно загружается одна подписка. Прежние серверы сохраняются
при ошибке загрузки, проверки или сохранения; успешное обновление заменяет только свою группу.
Выбор сохраняется по точной ссылке, затем единственному совпадению параметров
подключения, затем единственному имени при смене ключей; если сервер исчез, выбирается первый и активное соединение переключается.

Показываются `profile-title`, `announce`, `subscription-userinfo`, `support-url`
и `profile-web-page-url` из HTTP-заголовков и комментариев текстовой подписки,
включая Base64 и архивы. Объявления отображаются текстом; ссылки открываются
только по нажатию и только HTTPS. Трафик/срок действия берутся из ответа провайдера,
Velum не ведёт собственную историю потребления. Логирование и маршруты провайдера
не применяются. Форматы полей: [документация Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/app-management.md).

При переходе с 0.3 серверы сохраняются в «Импортированные». Старый URL не
сохранялся, поэтому ссылки подписок нужно добавить заново. После этого старую
группу можно удалить. Перед первой записью нового формата создаётся один
`settings-before-alpha.json` (0600) для отката. Новые настройки несовместимы с 0.3:
для возврата нужно закрыть Velum и восстановить этот файл как `settings.json`.

«Прокси» проверяет HTTPS через выбранный сервер и только после успеха включает
HTTP/HTTPS/SOCKS в настройках GNOME. Прежние настройки восстанавливает отдельный
процесс при отключении, завершении приложения и аварии GUI. Если принудительно убит и
этот процесс, восстановление выполняется при следующем запуске Velum.
Настройки, изменённые другим приложением, не перезаписываются.
Нужны `gsettings`, схемы GNOME, dconf и пользовательский сеанс D-Bus.
Приложения с собственными настройками прокси могут игнорировать настройки GNOME.

Для программ, которые не учитывают настройки прокси GNOME, используйте TUN.
Он направляет IP-трафик через `velum0` с учётом правил маршрутизации. Это не
меняет поддерживаемые сервером протоколы: поведение UDP и отдельных приложений
зависит также от сервера и выбранного транспорта.

Если конкретный Reality-профиль нестабилен с `fp=chrome`, можно проверить
отдельную копию ссылки с `fp=firefox`. Это явная настройка профиля: Velum не
подменяет fingerprint автоматически и не отключает проверку сертификатов.
Наблюдаемая разница fingerprint сама по себе не доказывает, какой участок сети
фильтрует соединение.

«Локально» открывает HTTP/SOCKS5 на `127.0.0.1:2080` без изменения настроек ОС
и без внешней проверки. Адрес нужно указать в нужном приложении; для SOCKS5
выбирайте удалённое разрешение DNS (`socks5h`). Статус сообщает только об открытом
порте. Локальные порты не требуют пароля: другие процессы вашего компьютера
также могут пользоваться ими. Из локальной сети они недоступны.

TUN требует установленного RPM/DEB той же версии, `/dev/net/tun` и подтверждения
polkit. Наличие устройства само по себе не означает наличие помощника Velum.
При запуске из проекта можно нажать «Установить обновление»: будет установлен
локальный пакет из `dist/` через системный менеджер пакетов. Это не включает VPN.
Интерфейс работает без root; повышенные права получает только помощник.
Подтверждение нужно один раз за сеанс приложения: помощник остаётся ждать
следующую команду после отключения TUN, без работающего сетевого ядра.
Закрытие/авария GUI закрывает его канал и останавливает помощник. При следующем
запуске требуется новое подтверждение. Постоянного сервиса и passwordless sudo нет.
Velum отказывается запускать TUN при обнаружении другого активного TUN-маршрута.
При доступном трее закрытие окна по умолчанию скрывает его и оставляет VPN работающим.
«Завершить Velum» отключает соединение. sing-box управляет маршрутами и DNS своего
TUN-интерфейса через systemd-resolved и убирает их при штатной остановке.
Восстановление после аварии на целевой системе ещё не подтверждено.
Kill switch доступен как отдельная экспериментальная настройка; подробности ниже.

В режимах «Прокси» и TUN статус подключения появляется после HTTPS-проверки
через отдельный локальный порт, принудительно направленный в выбранный сервер.
Пользовательские исключения не могут сделать эту проверку успешной через прямой
интернет. Проверяются `https://example.com/` и при неудаче
`https://www.gstatic.com/generate_204`, с проверкой сертификата и ограничением
6 секунд на каждый запрос и отдельным общим пределом 18 секунд для проверочного
процесса. При зависании, ошибке обоих адресов или завершении ядра подключение
отменяется; проверочный процесс останавливается и забирается его статус.
Это проверка при запуске, а не постоянный мониторинг доступности; фоновых пингов нет.

XHTTP-ссылки и нативный Xray JSON используют Xray; sing-box при этом
обслуживает локальный HTTP/SOCKS, исключения и TUN. Остальные ссылки
используют только sing-box. Xray запускается без root только на время
подключения, со служебным SOCKS-портом на `127.0.0.1`. В режиме TUN
адрес сервера разрешается заранее, а сокет Xray привязывается к внешнему
интерфейсу через `iproute2`, чтобы не попасть обратно в туннель.
Смена сети требует переподключения. Автоматического отключения другого VPN нет.

## Трей, автозапуск и восстановление

Трей использует StatusNotifierItem (AppIndicator). В нём доступны открытие окна,
подключение/отключение и завершение Velum. При исчезновении трея скрытое окно
возвращается. Если рабочий стол не поддерживает трей, окно не прячется; завершить
приложение можно в настройках. Повторный запуск открывает существующее окно.
В GNOME требуется поддержка AppIndicator/StatusNotifierItem со стороны рабочего стола.
Для скрытия и возврата окна Velum выбирает X11/XWayland, если доступен `DISPLAY`.
Графика использует EGL. В чистом Wayland без XWayland окно работает, но скрытие в
трей недоступно: используемая версия winit не реализует hide/show и активацию окна
для этого backend. Это ограничение отображается в настройках.

«Запускать при входе в систему» создаёт только пользовательский desktop-файл
в XDG autostart. «Подключаться при запуске» — отдельная опция, по умолчанию выключена.
Автозапуск скрывает окно только после регистрации доступного трея. Разрешение polkit
для TUN при новом сеансе приложения всё равно запрашивается.

Восстановление слушает State/PrimaryConnection NetworkManager и PrepareForSleep
systemd-logind через D-Bus. В простое потоки блокируются в ожидании событий.
События объединяются задержкой 2 секунды; повторные подключения после ошибки идут
через 2, 5, 15, 30, 60 и 120 секунд. После этого попытки прекращаются до действия
пользователя или нового события сети. Сон, отсутствие сети и ручное отключение
останавливают таймеры. Каждая попытка выполняет обычную проверку подключения.
Постоянных пингов и фонового мониторинга удалённого сервера нет. Если сервер завис,
но ядро и сеть остаются работающими, это не обнаруживается непрерывной проверкой.
Без NetworkManager автоматическая смена сети не отслеживается; это видно в настройках.

Названия и объявления поддерживают встроенные монохромные Noto Emoji, включая
флаги, оттенки кожи и составные символы Unicode 16. Флаги в этом шрифте представлены
контуром с буквенным кодом страны. Данные и URL подписок сохраняются в исходном Unicode;
подстановка глифов применяется только при отображении. Сеть для эмодзи не используется.

## Защита при обрыве TUN (экспериментально)

Опция выключена по умолчанию и работает только в TUN. Помощник создаёт собственную
таблицу `inet velum_guard`, не изменяя таблицы firewalld, Docker или других программ.
Она блокирует непредусмотренный выход с хоста и forwarding вне TUN. Разрешены loopback,
TUN, помеченные сокеты ядер и необходимый DHCP/IPv6 neighbor discovery.
Явные правила «Напрямую» выполняются внутри ядра и продолжают работать.
Forwarding-защита может ограничивать контейнеры и виртуальные машины: эту опцию
следует отдельно проверить для своей топологии.

Правила остаются между переключениями, при падении ядра и во время ожидания сети.
После исчерпания попыток трафик остаётся заблокированным до нового подключения или
ручного отключения. Ручное отключение, выход из приложения и штатная обработка EOF GUI
снимают правила. Это защита сеанса Velum, а не постоянная блокировка после закрытия
или аварии всего приложения. После SIGKILL самого помощника таблица может остаться.
Для восстановления обычного доступа закрыть Velum и выполнить:

```sh
pkexec /usr/libexec/velum/velum-tun --release
```

Команда удаляет только таблицу Velum с проверенным идентификатором владельца.
Для защиты нужны nftables и Linux 5.17+. В защищённом режиме Xray запускается
помощником под UID пользователя с единственной capability CAP_NET_RAW для SO_MARK;
он не получает root. sing-box для TUN остаётся привилегированным как прежде.
Для bootstrap используются помеченные DoH-запросы к Cloudflare 1.1.1.1, без разрешения
обычного прямого DNS в firewall. Xray bootstrap в этом режиме выбирает IPv4.
Без kill switch остаётся прежний путь запуска ядер.

## Маршрутизация

«Настроить правила» открывает редактор с отдельными профилями. Можно создавать,
копировать и переименовывать профили, искать правила, выбирать несколько строк,
включать/выключать их, менять маршрут и удалять одной операцией. Адреса можно вставлять
списком. Изменения остаются черновиком до «Применить» и вызывают одно переподключение;
«Отмена» и закрытие редактора их отбрасывают. Профиль выбирается на главном экране.

Правила применяются сверху вниз, первое совпадение определяет маршрут. Остальной
трафик идёт через VPN. Приложение выбирается из desktop-файлов или по полному пути
исполняемого файла. Такие правила действуют только в TUN. Запуск desktop-команд
не выполняется; Flatpak, контейнеры и приложения с отдельными сетевыми процессами
требуют проверки фактического пути процесса.

При обновлении с alpha.1 исключения автоматически переходят в профиль «Обычный»;
подписки и настройки сохраняются. Перед первой записью создаётся приватная копия
`settings-before-alpha2.json` (0600). Для отката закрыть Velum, вернуть прежний пакет
и восстановить этот файл как `settings.json`.


| Правило | Что идёт напрямую |
|---|---|
| `example.com` | Только `example.com` |
| `*.example.com` | `a.example.com`, `a.b.example.com`, но не `example.com` |
| `*.example` | Любой поддомен зоны `.example` |
| `192.168.1.20` | Один IP |
| `10.0.0.0/8` | Подсеть IPv4 |
| `2001:db8::/32` | Подсеть IPv6 |

Правила применяются в ядре; всё остальное идёт через выбранный сервер.
Чтобы обойти и корневой домен, и поддомены, добавьте обе записи.
Тестер проверяет введённый домен/IP синтаксически и не отправляет DNS-запрос.
CIDR проверяется по IP назначения; тестер не разрешает доменные имена в IP.
Доменная маршрутизация в TUN использует DNS reverse mapping и распознавание
HTTP/TLS/QUIC. Для приложений с собственным зашифрованным DNS, ECH или
подключением по IP имя может быть неизвестно: тогда применяются IP-правила
либо маршрут по умолчанию. Это ограничение доменных политик, а не обещание
распознавать любой скрытый домен.

DNS обычных проксируемых соединений: DoH к `1.1.1.1` через прокси.
Для доменных исключений: DoH напрямую. Начальное разрешение имени самого
сервера использует DNS системы. DNS-кэш только в оперативной памяти.

## Поддержка

- VLESS с TLS или Reality; TCP, WebSocket, gRPC, XHTTP; XTLS Vision.
- VMess AEAD (`alterId=0`) с TLS; TCP, WebSocket, gRPC.
- Trojan с TLS; TCP, WebSocket, gRPC.
- Shadowsocks AEAD / 2022, без SIP003-плагинов.
- Hysteria2 с проверкой TLS; опционально Salamander.
- Светлая / тёмная тема и пользовательский цвет акцента.

Новое VLESS encryption, WireGuard, TUIC, Clash YAML и зашифрованные
подписки Happ в Velum 1.0.0 не поддерживаются. XHTTP поддерживает `auto`,
`packet-up`, `stream-up`, `stream-one` и проверенные параметры `extra`/`xmux`;
вложенный `downloadSettings` пока отклоняется.
Импорт не отключает проверку сертификатов и не пытается молча заменить
неподдерживаемый транспорт. HTTPS-подписки загружаются по нажатию или выбранному расписанию,
с максимум тремя HTTPS-перенаправлениями и общим бюджетом 20 секунд на
TCP/TLS/HTTP, включая перенаправления. Блокирующий DNS системы может превысить
этот срок. HTTP-ошибки, таймауты, пустые ответы и HTML вместо подписки
показываются без адресов, ключей и тела ответа. URL хранится в закрытом файле настроек для обновлений.
Импорт атомарный: при ошибке любой строки весь новый список отклоняется.
Перед сохранением весь список проверяется соответствующими ядрами.
Известные группировочные поля `x-durev-block` и `x-durev-prio` не меняют
соединение и пропускаются. Для `x-durev-sni-change` принимаются только
`true/false/1/0`; включённая подсказка требует явного `sni` или `peer`.
Расширение публично не описано: Velum сохраняет SNI из ссылки без собственной
подмены или ротации имени. Неизвестные параметры подключения отклоняются.
Поле `concurrency` в VLESS/Trojan-ссылках принимается как неактивная настройка
Xray Mux: само по себе оно не включает Mux. `mux=false` / `mux=0` принимаются,
`mux=true` / `mux=1` отклоняются с объяснением. Включённый Xray Mux не заменяется
на несовместимый sing-box multiplex. Настройки TLS и Reality проверяются как раньше.
Семантика выключенного Mux: [документация Xray](https://xtls.github.io/en/config/outbound.html#muxobject).

Формат ответа определяется по содержимому, а не по URL, расширению или
`Content-Disposition`. Поддерживаются UTF-8 / Base64-списки ссылок,
JSON с `outbounds` Xray или sing-box, массив таких конфигураций, ZIP, gzip,
TAR и tar.gz. Импорт JSON извлекает только поддерживаемые параметры серверов;
провайдерские inbounds, логирование, DNS и маршруты не применяются.
Xray JSON хранится как нормализованный профиль `velum-xray://`, с исходными
настройками поддерживаемого транспорта; это внутренний формат, не ссылка
подписки. Поддержан Xray Hysteria2 (`protocol: hysteria`, `version: 2`),
включая QUIC congestion. Отладка QUIC и Reality отключается независимо
от настроек провайдера. Повторяющиеся конечные профили удаляются.
Селекторы sing-box превращаются в обычный список конечных серверов.
Чтение архивов происходит в памяти, без извлечения на диск и запуска файлов.
Поддерживаются BOM, комментарии и до двух слоёв Base64, включая JSON внутри.
Повреждённый распознанный конфиг в архиве отклоняет всё обновление; README
и лицензии не принимаются за серверы и не меняют метаданные подписки.
Ограничения: 2 МиБ загружаемых данных, 2 МиБ суммарной распаковки,
32 файла, 3 уровня вложенности и 256 серверов. Парольные архивы, RAR, 7z
и неизвестные схемы JSON отклоняются. В поле импорта можно указать и
абсолютный путь к локальному файлу.

## Разработка и сборка

Rust зафиксирован в `rust-toolchain.toml`, зависимости — в `Cargo.lock`.
При локальной установке компилятора используется `.tools/`; системный PATH
и пользовательские настройки Rust проект не меняет.

```sh
. ./scripts/env.sh
python3 scripts/fetch-core.py
python3 scripts/fetch-xray.py
python3 scripts/fetch-portable-tools.py # для glibc baseline, Linux x86_64
./scripts/check.sh
python3 scripts/fetch-appimage-tools.py  # только для AppImage x86_64
./scripts/build.sh
```

Требования сборки: Rust, C/C++ toolchain, pkg-config, Python 3.11+, GNU binutils;
`rpm-build` для RPM. Dev-пакеты GTK/WebKit не нужны. На Fedora:
`gcc gcc-c++ make pkgconf-pkg-config binutils rpm-build`.
`--skip-appimage` исключает AppImage из локальной сборки.
Нативную arm64-сборку можно выполнить на Linux arm64 без x86_64 Zig tools;
она здесь не проверена. Без Zig tools build.sh использует системный ABI,
поэтому такая сборка может требовать более свежую glibc.

Для теста TCP/Reality нужны Python 3 и команда `openssl`: временный TLS-сервер
и синтетические ключи создаются только на IPv4 loopback и удаляются после теста.

Тесты поднимают локальные серверы и отдельный сеанс D-Bus с временным каталогом
настроек. Маршруты, системный DNS и настройки рабочего стола пользователя они
не меняют и настоящей подписки не требуют. QA-снимки интерфейса:

```sh
cargo build --locked --features qa
XDG_CONFIG_HOME="$PWD/work/qa-empty" EFRAME_SCREENSHOT_TO="$PWD/work/ui.png" target/debug/velum
```

**Функция `qa` только для тестов:** разрешает диагностический вывод и снимок
окна. Поставляемые сборки создаются без `qa`; не используйте QA-сборку с
личными ключами. `scripts/build.sh` её не включает.

Архитектура: `import.rs` проверяет ссылки; `routing.rs` задаёт семантику
политик; `config.rs` генерирует ограниченную конфигурацию; `process.rs`
управляет временем жизни обоих ядер; `xray.rs` проверяет нативные профили;
`storage.rs` сохраняет настройки атомарно; `system_proxy.rs` управляет GNOME
и восстановлением прокси, `connectivity.rs` проверяет HTTPS при подключении;
`ui.rs` рисует интерфейс только по событиям. Привилегированный помощник
принимает типизированный запрос, а не произвольный sing-box JSON.

## Границы первой версии

Нет обновления самого приложения и публичного аудита безопасности. Восстановление
зависит от событий NetworkManager/systemd-logind; постоянный мониторинг удалённых серверов отсутствует.
TUN требует отдельного тестирования на целевой системе. Проверки реальных
подписок описаны в `docs/VERIFICATION.md`; они не гарантируют доступность
каждого сервера. Улучшение батареи/скорости относительно Happ пока не измерялось.
При использовании Xray работают два ядра, что добавляет расход памяти и
передачу данных через loopback; этот расход ещё не измерен.

Лицензия Velum: GPL-3.0-or-later. См. `THIRD_PARTY.md` и `PRIVACY.md`.

## Измерение нагрузки

Для CPU, RSS, context switches и page faults (пакет sysstat):

```sh
pidstat -u -r -w -G '^(velum|velum-tun|sing-box|xray)$' 1 60
```

Сравнить минуту простоя со скрытым окном и одинаковую нагрузку с открытым окном.
Если работает другой VPN на этих же ядрах, фильтр включит и его процессы — выбрать
нужные PID через `ps -eo pid,ppid,comm` и использовать `pidstat -p PID1,PID2,...`.
`free -h` показывает память всей системы, `iotop` — дисковый ввод-вывод, поэтому
они не заменяют этот замер. RSS процессов может учитывать общие страницы несколько раз.
Пробуждения и расход батареи дополнительно оценивать через powertop на одинаковой
нагрузке/яркости экрана; эти системные показатели нельзя приписывать одному приложению.
Результаты теста stdout не являются журналом активности пользователя.

## Проверка VLESS TCP/Reality

```sh
python3 scripts/diagnose-link.py --uplink
```

Ссылка вводится скрыто. Скрипт запускает отдельный локальный Xray и проверяет
HTTP и HTTPS по домену и числовому IPv4. `--uplink` привязывает только тестовые
сокеты к основному внешнему интерфейсу, не изменяя маршруты, DNS или активный VPN.
Без этого флага используется системный маршрут; скрипт предупреждает, если он
проходит через существующий TUN. `--without-vision` явно отключает Vision только
для сравнительного теста; защита Reality сохраняется.
Ключи и конфигурация не сохраняются, тела ответов отбрасываются; логи ядер отключены.
Результат содержит только доступность, коды curl/HTTP и длительность запросов.
Успех TCP и обычного TLS сами по себе не подтверждают авторизацию Reality/VLESS.

## GitHub Actions и выпуск

`.github/workflows/release.yml` запускается для PR, push в main/master, тегов `v*`
и вручную. Точная версия Rust задана в rust-toolchain.toml; Cargo.lock обязателен.
Action-зависимости закреплены полным commit SHA, ядра и Zig — контрольными суммами.

Pipeline проверяет fmt/clippy/tests, собирает x86_64 DEB и RPM с ABI glibc 2.31,
проверяет содержимое пакетов, затем устанавливает их в отдельных контейнерах
Debian 13 и Fedora 44. Smoke test проверяет зависимости, права, версии, desktop/
polkit-метаданные и локальное разрешение DNS. Он не заменяет GUI/TUN-тест на ВМ.
Временный GitHub runner разрешает user namespaces для изолированных nftables-тестов.

Пакеты, portable/source-архивы и SHA256SUMS сохраняются как Actions artifacts
на 14 дней. Тег `v1.0.0` должен совпадать с Cargo.toml. Только push тега после
успеха всех проверок создаёт **черновик GitHub Release**; публикация выполняется
вручную после просмотра. Повторный запуск не перезаписывает существующий релиз.
Токен чтения используется для проверок, contents:write — только для release job.
PR не получает секреты или права публикации; pull_request_target не используется.

Специальные GitHub Secrets не нужны. Перед первым выпуском включите Actions,
защитите основную ветку и теги `v*` от посторонних изменений. Пакеты пока без
GPG-подписи; SHA256SUMS проверяет целостность, но не заменяет подпись издателя.
AppImage собирается локально; pipeline намеренно выпускает запрошенные DEB/RPM.

Локальное повторение проверок установки, без изменения хоста:

```sh
CONTAINER_ENGINE=podman scripts/smoke-container.sh debian
CONTAINER_ENGINE=podman scripts/smoke-container.sh fedora
```
