# Конфиденциальность

Eivro хранит настройки на компьютере пользователя. Приложение не отправляет
телеметрию и не ведёт историю посещений или подключений. Ниже описаны данные,
которые сохраняются для работы, и сетевые обращения приложения.

## Журналы и диагностика

В обычной сборке Eivro:

- Нет аналитики, телеметрии, идентификаторов установки, crash reporting,
  журнала подключений, истории DNS/адресов/трафика или фонового обновления самого приложения.
- Нет файлов логов. В sing-box установлено `log.disabled=true`, в Xray —
  `loglevel=none`, `access=none`, `error=none`, `dnsLog=false`.
  stdout и stderr обоих ядер перенаправлены в `/dev/null`, дисковый кэш выключен.
  Отладка Reality и QUIC принудительно отключена. Конфигурация провайдера
  не может включить логи, статистику, observatory или открыть свои inbounds.
- Rust logging отключён на этапе компиляции. Вывод GUI также закрыт;
  сообщения об ошибках существуют только в текущем состоянии интерфейса.
- Дампы памяти отключаются для процессов приложения и наследуются ядром.
  Конфигурация ядра передаётся через stdin, без секретов в аргументах
  командной строки и без временного файла конфигурации.
- Супервизор ждёт события процесса/канала; нет фонового опроса статистики,
  тестов скорости, периодического ping или бесконечных анимаций.

## Что сохраняется

Настройки, выбранный сервер, импортированные ссылки/профили с ключами,
URL подписок, информация провайдера, интервал и время последнего успешного
обновления, профили маршрутизации с адресами/путями программ, тема и локальный порт в `$XDG_CONFIG_HOME/eivro/settings.json`
(обычно `~/.config/eivro/settings.json`). Это конфигурация, а не журнал.
Папка имеет права `700`, файл — `600`, запись атомарная. Ключи в этом файле
**не зашифрованы**: они защищены правами доступа пользователя. Удаление
сервера убирает ключ из текущих настроек; это не гарантирует физического
стирания данных с SSD, резервных копий или снимков файловой системы.

При первой миграции со схемы 0.3 создаётся единственная приватная копия
`settings-before-alpha.json` (0600) для отката. Она содержит прежние ключи;
удаление подписки из актуальных настроек не удаляет эту копию автоматически.
При миграции alpha.1 создаётся аналогичная единственная копия `settings-before-alpha2.json`.
История обновлений не ведётся, ошибки обновления остаются только в памяти.

Во время работы системного прокси в той же папке сохраняется
`proxy-recovery.json` (0600): прежние и применённые настройки GNOME для
восстановления после аварии. После восстановления файл удаляется.
`proxy.lock` предотвращает одновременное управление из двух окон Eivro.
Эти файлы не содержат истории соединений, DNS-запросов, трафика или временных меток.

## Сетевые обращения

При ручном или автоматическом обновлении Eivro обращается к серверу подписки.
URL сохраняется с правами 0600. Расписание выбирается для каждой подписки:
вручную, интервал провайдера или собственный интервал. Таймер работает только
при работающем приложении, включая скрытое в трее окно. Загрузка ограничена 20 секундами и 2 МиБ. Разрешены
до трёх перенаправлений только на HTTPS, без Referer и HTTP Basic Auth. Получатель
подписки видит IP и этот запрос. Ядро соединяется с выбранным сервером,
адресами, указанными пользовательским трафиком, и DNS, описанным в [справке](docs/REFERENCE.md#dns).
Обычный DNS-кэш в памяти нужен для маршрутизации и работы соединения;
после завершения ядра он исчезает.

При подключении в режимах «Прокси» и TUN выполняется HTTPS-проверка
`https://example.com/`, при неудаче — `https://www.gstatic.com/generate_204`.
Оба запроса идут только через выбранный сервер; получатель видит выходной IP
этого сервера. Проверка не содержит ключей подписки, идентификатора установки
или статистики, её результат не сохраняется. В режиме «Локально» этих запросов нет.
После подключения периодических проверок не выполняется.

Политика относится к Eivro и обоим дочерним ядрам. Она не управляет журналами
ОС/polkit, серверов, DNS-провайдеров, других приложений и содержимым swap.
Отдельная QA-сборка с feature `qa` предназначена только для синтетических
тестов; она не включается в поставляемые пакеты.

Трей и наблюдение за сетью/сном используют локальный D-Bus; периодического опроса
нет. Восстановление имеет ограниченное число попыток с растущими паузами. Каждая
попытка использует обычную HTTPS-проверку подключения, без сохранения результатов.
Эмодзи встроены в исполняемый файл, внешних загрузок изображений нет.

Опциональный автозапуск сохраняет desktop-файл в XDG autostart без URL и ключей.
Один экземпляр приложения определяется локальным сокетом с проверкой UID;
по нему передаётся только команда открытия окна, без конфигурации или секретов.

Экспериментальная защита TUN создаёт собственную таблицу nftables без logging/counters.
При восстановлении Xray bootstrap разрешает имя сервера через DoH к 1.1.1.1; DNS-провайдер
видит имя сервера и исходный IP. История этих запросов Eivro не ведётся.

При переходе с 1.0.0 на 1.1.0 создаётся `settings-before-1.1.json` (0600).
Она содержит прежние настройки и ключи; храните её так же, как основной файл.
Сетевой выход с DNS интерфейса читает конфигурацию systemd-resolved по запросу
и при событиях сети. DNS-запросы правил идут к выбранному DNS через выбранный
интерфейс, без публичного резервного DNS. События и запросы не журналируются.

## Переход с Velum

В Eivro 1.2.0 каталог `$XDG_CONFIG_HOME/velum` (обычно `~/.config/velum`)
при первом запуске атомарно переносится в `eivro`. Файлы с ключами и резервными
копиями сохраняют свои права; их содержимое не выводится и никуда не отправляется.
Управляемый старый файл автозапуска сохраняется с окончанием `.desktop.before-eivro`.
При конфликте каталогов или повреждённых старых настройках автоматическое объединение не выполняется.

## macOS

Пути настроек, системные DNS-обращения и данные восстановления macOS описаны
в [платформенной заметке](docs/MACOS.md#данные). Снимок DNS/прокси не содержит
истории трафика и удаляется после восстановления. Авторизация передаётся
помощнику через локальный сокет и не записывается в файлы. Системные журналы
macOS и Apple crash reporting не управляются политикой приложения.
